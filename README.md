## What's included

- **Flutter UI**: Arabic RTL, responsive desktop/tablet layout; login; user management; management dashboard; branch-wide cash shifts; POS with fractional quantities, cash/card/wallet/bank split payment, credit sale; product/stock views; purchase entry; customer/supplier records; expenses; document history.
- **Branch service**: HTTP REST API backed by SQLite in WAL mode, one transaction per write command, explicit `Idempotency-Key`, PBKDF2 password hashing, hashed expiring opaque sessions, tenant + branch-scoped queries, role authorization, immutable audit trail.
- **Financial core**: Egyptian piasters as integer values, quantity in thousandths of the smallest base unit, weighted-average inventory cost by warehouse, sales/purchases, full/partial settlement, customer credit limits, supplier payables, posted returns, expense accounting, stock adjustments, raw-to-packaged preparation, journal balancing and sync outbox. Schema v2 adds alternate carton/box units with separate exact selling prices and barcode lookup.
- **Source**: complete consolidated requirements under [`docs/MASTER_SPEC.md`](docs/MASTER_SPEC.md), executable tests in server and Flutter packages, setup scripts.

## Tech stack

- Flutter SDK / Dart 3.4+ frontend (`app/`)
- Dart / Shelf HTTP branch host (`server/`)
- Local SQLite (foreign keys + WAL) on the host, never shared over SMB
- SQLite database files and local credentials are **not** committed.

## Prerequisites

Install stable Flutter and Dart. Make sure `flutter --version`, `dart --version`, and `flutter doctor` work. On Windows, enable Desktop development with Visual Studio C++ tools. For Android deployment, install Android SDK and USB drivers.

### 1. Bootstrap the branch server

From `server/`:

```powershell
# PowerShell: choose and keep a strong admin password
$env:KASHER_ADMIN_PASSWORD = Read-Host "Admin password"
dart pub get
dart run bin/kasher_server.dart --db=data/kasher.sqlite3 --name="متجر المثال" --branch="الفرع الرئيسي" init
```

Write down the printed `tenant_id`, `branch_id`, `warehouse_id`; no fake data is created. Then:

```powershell
dart run bin/kasher_server.dart --db=data/kasher.sqlite3 serve
```

Default URL: `http://127.0.0.1:8787`. The default binding is restricted to the local machine for safety.

For devices on a **trusted isolated LAN only**:

```powershell
dart run bin/kasher_server.dart --db=data/kasher.sqlite3 --bind=0.0.0.0 --port=8787 serve
```

Allow inbound access only from the branch VLAN or trusted subnet using Windows Firewall. Do not port-forward this service; **plain HTTP over LAN is a development limitation** until TLS/pairing is implemented.

### 2. Generate native Flutter platform scaffolds and run UI

From `app/`:

```powershell
flutter create --project-name kasher_app --platforms=windows,android .
flutter pub get
flutter run -d windows
# Or: flutter run -d <android-device-id>
```

On an Android device, enter the Windows host's trusted LAN address (e.g., `http://192.168.x.x:8787`) instead of localhost. Cleartext HTTP may be blocked by modern Android; implement and configure TLS before any production use. Native Windows / Android scaffold files are generated by Flutter on your machine; this archive intentionally avoids claiming it contains tested binaries.

### 3. Tests

```powershell
cd server
dart test
dart analyze
cd ../app
flutter test
flutter analyze
```

Tests run on GitHub hosted runners; the latest results and any failures are visible under the Actions tab. These are **not** substitutes for field tests and legal certification.

## API quick start

`POST /api/v1/auth/login` with `tenant_id`, `username`, and `password` returns a bearer token. `GET /api/v1/branches`, `/products`, `/customers`, `/suppliers`, `/stock?branch_id=...`, `/documents?branch_id=...`, `/dashboard?branch_id=...`, `/audit?branch_id=...`. Writes use JSON plus Bearer token and unique `Idempotency-Key` header. See [`docs/API.md`](docs/API.md).

## Security & accounting guarantees (current implementation)

- SQLite atomic write transactions, foreign keys, explicit no-negative-stock, WAC on each warehouse, double-entry balancing, rejected duplicate write keys, tenant/branch checks, role-based permission checks on server.
- Card and wallet are **recording methods**, not actual bank integrations. There is no connection to payment gateways.
- All financial reports are operational estimates and **not** legal e-invoices, regulatory certification or final audited accounting statements.
- The sync outbox durably records local events; it is **not** yet connected to any cloud synchronization service.

**Never deploy this development build to a live supermarket without completing the remaining release gates.**


### Audited cycle counts (development schema v5)

The Arabic **الجرد المعتمد** module captures warehouse inventory without
posting financial movements until an independent owner/manager approves.
Intervening sales or other warehouse stock movements invalidate the count,
requiring a new count. See [Arabic stocktake guide](docs/STOCKTAKE_AR.md).

### HTTPS-only remote branch connections

The Dart server refuses non-loopback HTTP and requires --tls-cert / --tls-key for LAN listening. Flutter rejects plaintext remote server URLs before authentication. See [Arabic trusted HTTPS setup](docs/HTTPS_LAN_AR.md). Basic one-time device pairing, active device sessions and revocation are implemented; hardware attestation, managed certificate lifecycle and production security assessment remain open.

### Branch device enrollment (schema v6)

The branch now uses per-device credentials, owner/manager-issued one-time 10-minute pairing tickets, Windows/Android OS-protected client secrets and revocable device-bound sessions in LAN mode. For first-branch registration and a real device revocation walkthrough, read the [Arabic device pairing guide](docs/DEVICE_PAIRING_AR.md). **Not** hardware device attestation or complete production authorization.

### Carton purchases and goods receiving

Purchase invoices may now receive configured product units (box/carton) by integer `unit_count` with independent exact `unit_cost_minor` per carton; quantities convert to base-stock thousandths. Paid invoices, supplier payables, expiry-lot intake and partial supplier returns remain transactionally audited. The Arabic Flutter purchases screen exposes unit selection. See [API purchase-by-carton semantics](docs/API.md#purchase-by-carton--alternate-unit).

### Scheduled promotional prices (development schema v7)

Owners/managers can configure nonoverlapping UTC time-window sale prices per base product or carton. The Dart server enforces final price at posting, and Flutter displays the effective price. See [Arabic promotions guide](docs/PROMOTIONS_AR.md). Coupons, conditional campaigns, per-branch pricing and customer-facing price re-confirmation are still excluded.


### Shared-database inter-branch shipments (schema v8)

The Arabic inter-branch shipments screen supports a two-phase dispatch and independent receipt, WAC in-transit ledger, lot identity preservation, and cancellation before receipt. This works **only when both branches share the same SQLite server**; offline cross-host replication remains a release blocker. See [Arabic guide](docs/BRANCH_SHIPMENTS_AR.md).


### Verified secondary encrypted backup storage

One-shot `tools/scheduled_backup.py` can optionally run `--offsite-directory <protected-share> --scratch <trusted-local-directory>` before deleting any old local copies. The offsite copy is promoted only after an independent authenticated restore and accounting audit on the trusted host. It does not set up Google Drive OAuth, secure scheduling, physical offsite storage or a tested disaster-recovery plan. See [Arabic offsite backup guide](docs/BACKUP_OFFSITE_AR.md).
