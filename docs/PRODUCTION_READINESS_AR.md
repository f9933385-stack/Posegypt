# جاهزية الإطلاق التجاري — حالة موثّقة ومهام تشغيل Posegypt

هذه الوثيقة تسجّل ما نُفّذ واختُبر، ولا تمنح اعتمادًا ضريبيًا أو أمنيًا أو محاسبيًا.
**الحالة: نسخة تطوير قابلة للبناء — ليست إصدارًا تجاريًا معتمدًا بنسبة 100%.**

## ما نُفّذ فعليًا

- تطبيق Flutter للعربية وWindows وAndroid، مع عمليات بيع وشراء أساسية ووردية وتقارير.
- خدمة Dart/Shelf/SQLite بعمليات ذرية ومعاملات Idempotency-Key ودفتر مزدوج القيد.
- بيع بكمية أساس كسرية أو بوحدة بديلة (كرتونة/علبة) لها معامل تحويل وسعر مستقل.
- قاعدة البيانات v2 مع ترحيل تدريجي من v1، ورفض فتح قاعدة بيانات أحدث من نسخة البرنامج.
- اختبار عودة المخزون والديون بعد إعادة تشغيل SQLite، وحماية المرتجعات الجزئية من فقد القروش.
- نسخة احتياطية مشفرة AES-256-GCM، مع اختبار فك التشفير والتدقيق، ومنع تزامن تشغيل نسختين، وسياسة احتفاظ محافظة.

## تشغيل نسخة احتياطية موثّقة

**المتطلبات:** Python 3.12، وملف SQLite تابع فعلاً لخادم Kasher، وكلمة مرور طويلة
تُحقن عند التشغيل من خزنة أسرار موثوقة، ومجلد احتياطي منفصل خاص وغير مكشوف للعموم.

من جذر المستودع:

```powershell
python -m pip install -r tools/requirements-backup.txt
# اضبط KASHER_BACKUP_PASSWORD داخل جلسة التشغيل من مصدر أسرار آمن.
python tools/scheduled_backup.py server/data/kasher.sqlite3 D:/KasherPrivateBackups --keep 14
```

عند النجاح تُرجع الأداة JSON فيه `status: verified` واسم ملف النسخة.
تُجرى الخطوات التالية بالترتيب: تدقيق المصدر → لقطة SQLite متسقة مع WAL →
تشفير AES-GCM → استعادة مؤقتة للتحقق → تدقيق المستعاد → تقليص عدد النسخ
السابقة إن تجاوز الحد. إذا فشلت الاستعادة **لا تُحذف نسخة قديمة**.
يُمنع تشغيل مهمتين متوازيتين بقفل `.kasher-backup.lock`؛ في حال بقاء
القفل بعد انقطاع كهرباء يجب أن يتحقق المشغّل من توقف المهمة قبل حذفه.

**قيود فعلية:** هذا أمر تشغيل واحد، وليس مجدولًا داخل Windows تلقائيًا.
تتطلب الجدولة ربط Windows Task Scheduler وخزنة أسرار مناسبة تحت حساب الخدمة،
ومراقبة فشل المهمة وإجراء اختبار استعادة ميداني. يجب حفظ نسخة مشفرة خارج الجهاز
والفرع؛ لا يوجد تكامل Google Drive OAuth بعد. تستخدم عملية SQLite snapshot
نسخة مؤقتة غير مشفرة **بمجلد مصدر قاعدة البيانات على جهاز الفرع** لا داخل
مجلد النسخ الخارجي؛ احمِ قرص الخادم بتشفير الجهاز وصلاحيات NTFS محكمة.

### استعادة طارئة

1. أوقف خادم Kasher وكل عمليات الكتابة إليه.
2. احتفظ بنسخة جنائية من الملفات الحالية دون تعديلها.
3. استعد إلى مسار جديد تمامًا لا يحتوي على قاعدة قائمة:

```powershell
python tools/backup_database.py restore D:/KasherPrivateBackups/FILE.kasherbak D:/KasherRecovery/verified.sqlite3
python tools/audit_database.py D:/KasherRecovery/verified.sqlite3
```

4. تحقق من الفواتير الأخيرة والأرصدة ومفاتيح التكرار وملفات WAL، ثم أعد
الخادم للخدمة وفق خطة استعادة معتمدة. لا تستبدل قاعدة البيانات الحية أثناء عمله.

## الوحدات البديلة والكرتونة

في شاشة الأصناف اختر «إضافة وحدة بيع»، أدخل اسم الوحدة وعدد وحدات الأساس
الداخلية وسعرها الخاص وباركودًا اختياريًا. من الكاشير اختر زر الكرتونة بجوار
الصنف، وستُسجل الفاتورة بالسعر المستقل والكمية الفعلية المخزنية.

العمليات المخزنية تستعمل دائمًا عدد الأجزاء الألفية لوحدة الأساس، بينما
البيع بالوحدة البديلة يسجّل إجمالي السطر المالي الأصلي، حتى تُستعاد مبالغ
المرتجعات الجزئية بالقرش الصحيح. يتضمن هذا Tests لبيع كرتونة وإعادة
نصفين ورصيد المخزون والقيود.

**لا تعتبر هذه الميزة جردًا كاملاً للتشغيلات وتواريخ الصلاحية أو تحويل
الوحدات في الشراء والاستلام؛ تلك مهام منفصلة لم تُعتمد.**

## بوابات إطلاق ما زالت مفتوحة

- حماية LAN باستخدام TLS موثوق وآلية إقران للأجهزة بدل HTTP التجريبي.
- مزامنة حقيقية بين الفروع دون تكرار أحداث، ومراجعة تعارض المخزون عند العودة.
- تشغيلات الصلاحية/FEFO وتطبيق الفاقد والجرد الواقعي والميزان المتغير.
- بنية خزائن وأدراج متعددة ووثائق تسوية نقدية ومطابقة المدفوعات.
- طباعة إيصالات 58/80 مم وملصقات وقراءة موازين على موديلات فعلية معروفة.
- ترخيص سنوي بتوقيع رقمي ومفاتيح إصدار تُدار خارج التطبيق.
- متطلبات مصلحة الضرائب المصرية الحالية والتكامل الرسمي/الاعتماد عند اللزوم.
- تثبيت Windows موقع/اختبارات تشغيل ميدانية وAndroid موقّع للإنتاج.
- تشغيل النسخ دوريًا، استعادة دورية خارج الجهاز، ومراقبة الانقطاع والتنبيهات.
- إجراء سيناريوهات القبول الـ34 والاختبارات الأمنية ومطابقة بيانات متجر تجريبي.

**لا تسجل بيانات بطاقة بنكية أو CVV، ولا تستخدم البرنامج في متجر حقيقي
قبل إغلاق بوابات الإصدار وتوثيق الاختبارات.**

## إضافة قيد العمل: التشغيلات والصلاحية

تم تنفيذ مخطط v3 للتشغيلات وسجل حركتها مع FEFO في الشراء والبيع والمرتجعات والتحويلات المحلية والتسويات. يتم رفض بيع المنتهي والكمية غير المدعومة بتشغيلات صالحة، وتُمنع عملية تجهيز الأصناف المتتبعة لحين بناء مسار توريث التشغيلات. تبقى إدارة الاستدعاءات والحجر والإتلاف والجرد المتزامن وتسوية المخزون القديم بلا تاريخ معروف ضمن **بوابات الإنتاج غير المكتملة**؛ لا يصح الادعاء أن إدارة صلاحية الغذاء اكتملت بهذه الإضافة. التفاصيل في [دليل التشغيلات](EXPIRY_LOTS_AR.md).

**تطوير v4:** أُضيف حجز تشغيلات مع سجل أسباب وصلاحية فصل بين الحجز (مسؤول مخزون) وفك الحجز (مدير/مالك). تُستبعد الكمية المحجوزة من FEFO، لكن إدارة سحب المنتجات من السوق والإتلاف الرسمي ما زالا غير مكتملين.


## الجرد الدوري المعتمد (مخطط v5)

أُضيف جرد فعلي بمرحلة إدخال عدّ منفصلة عن اعتماد فروق الكمية والتكلفة:
يمنع الموظف من اعتماد الجرد الذي أنشأه، ويُرفض الجرد إذا تحرك المخزون
أثناء فترة العدّ. يدعم الجرد الأرصدة بوحدة الأساس والتشغيلات المسجلة.
ما زال جرد مواقع متعددة غير متصلة، والعدّ الأعمى الثاني، وربط ماسحات
الأجهزة ومراجعة الفروق الكبيرة بحاجة إلى اعتماد تجاري واختبار ميداني.
[دليل الجرد](STOCKTAKE_AR.md).

## حماية الاتصال بين أجهزة الفرع

أُضيف إلزام HTTPS لأي خادم خارج loopback ورفض إرسال بيانات الدخول عبر HTTP إلى جهاز بعيد. ما زال إقران الأجهزة وإبطال الأجهزة وتوزيع جذور الشهادات وتدويرها غير مكتمل. راجع [دليل HTTPS لشبكة الفرع](HTTPS_LAN_AR.md).

## إقران أجهزة الفرع (مخطط v6)

أضيف إقران أجهزة الكاشير برمز مؤقت أحادي الاستخدام وتخزين سرّ مستقل لكل جهاز في Windows/Android Secure Storage. تتطلب جلسات الشبكة الآن هوية جهاز نشطة وحساب موظف، ويمكن للمدير أو المالك إيقاف الجهاز وإبطال الجلسات. لا تزال شهادة سلامة الأجهزة العتادية، والتوزيع المؤسسي للشهادات والمفاتيح، والمراقبة الأمنية والاختبار الميداني ناقصة. راجع [دليل إقران الأجهزة](DEVICE_PAIRING_AR.md).

## شراء وتوريد بالكرتونة

يدعم قسم المشتريات الآن اختيار وحدة الأساس أو كرتونة/علبة مضافة للصنف، ثم إدخال عدد الكراتين الصحيح وتكلفة شراء الكرتونة مستقلة عن سعر بيعها. يحوّل محرك الخادم الكمية إلى المخزون الأساسي، ويحتفظ بالتكلفة والقروش الأصلية في فاتورة الشراء؛ كما يظل رقم التشغيلة وتاريخ الصلاحية إلزاميين عند استلام الأصناف المتتبعة. وتستمر مرتجعات المورد بالكمية الأساسية على المستند الأصلي. هذه إضافة برمجية واختبارية، وليست اعتمادًا لكل سياسات مشتريات وسجلات الموردين.

## عروض الأسعار V7

أُضيف السعر الترويجي المجدول للقطعة والكرتونة مع تحكم المدير وعدم تجاوز الكاشير للسعر. بقيت العروض المركبة والكوبونات والعروض حسب الفرع والولاء وإعادة تأكيد الإجمالي عند اعتماد الطلب والاختبار الميداني غير مكتملة. راجع [دليل العروض](PROMOTIONS_AR.md).
