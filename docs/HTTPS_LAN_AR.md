# إعداد HTTPS داخل شبكة الفرع — Posegypt

**الحالة:** أُضيف رفض صريح لاتصال HTTP البعيد على الخادم وتطبيق Flutter. هذا لا يساوي اعتماد أمني تجاريًا ولا ينجز إقران الأجهزة.

## ما يفرضه البرنامج
- HTTP مسموح فقط على 127.0.0.1 أو localhost أو ::1 داخل الجهاز نفسه.
- تشغيل خادم على 0.0.0.0 أو عنوان LAN يتطلب شهادة TLS ومفتاحًا مطابقًا؛ التشغيل من دونهما مرفوض.
- عميل Flutter يرفض عنوان HTTP غير محلي قبل إرسال اسم المستخدم أو كلمة المرور أو توكن الجلسة.
- يتم التحقق من سلسلة شهادة HTTPS واسم المضيف عبر نظام التشغيل؛ لا يوجد تجاوز لقبول شهادات مجهولة.
- لا تقبل شاشة الدخول رابطًا به كلمة مرور أو معاملات URL أو مسارات إضافية.

## التشغيل الموثوق
1. استخدم اسم DNS داخليًا ثابتًا مثل pos-branch1.example.com يشير إلى خادم الفرع. أصدر شهادة موثوقة تتضمن الاسم ضمن SAN ويثق بها Windows وAndroid.
2. خزّن سلسلة الشهادة والمفتاح خارج GitHub على قرص خادم محمي بصلاحيات نظام الملفات وتشفير القرص.
3. من داخل مجلد server شغّل: dart run bin/kasher_server.dart --db=data/kasher.sqlite3 --bind=0.0.0.0 --port=8787 --tls-cert=C:/KasherSecrets/branch.fullchain.pem --tls-key=C:/KasherSecrets/branch.key.pem serve
4. إذا كان المفتاح مشفرًا، قدّم KASHER_TLS_KEY_PASSWORD من خزنة أسرار أثناء التشغيل، وليس ضمن وسيطات الطرفية أو المستودع.
5. على الأجهزة أدخل https://pos-branch1.example.com:8787. تأكد أن curl.exe --fail https://pos-branch1.example.com:8787/health يعمل **دون تعطيل التحقق من الشهادة**.
6. افتح منفذ الخدمة لجهاز الكاشير المصرح له فقط بواسطة جدار حماية الشبكة المحلية، ولا تفتح أي تحويل Port Forward على الراوتر إلى الإنترنت. بعد تجديد الشهادة، أعد تشغيل الخدمة.

## لا يزال غير مكتمل
- إقران أجهزة الكاشير وإبطال الأجهزة المسروقة والمصادقة المستقلة لكل جهاز.
- توزيع جذور شهادات CA المؤسسية وتدوير الشهادات تلقائيًا وتوثيق دورة المفاتيح على Windows وAndroid.
- اختبار اختراق ميداني ومراقبة محاولات الدخول والتأمين على شبكات المتاجر المختلفة.
- مزامنة الفروع والامتثال الضريبي والطباعة والتراخيص والاختبارات الميدانية.

**تنبيه:** شهادة HTTPS الخاصة بالخادم تثبت هوية الخادم عند إعداد الثقة الصحيح، لكنها لا تثبت تلقائيًا أن كل جهاز كاشير مسموح له بالاتصال.

**تحديث v6:** تتطلب خدمة HTTPS في وضع LAN الآن جهازًا مقترنًا فعالًا، بالإضافة إلى حساب الموظف. أبدأ إقران الجهاز الأول على خادم loopback ثم انتقل إلى HTTPS. راجع [خطوات الإقران](DEVICE_PAIRING_AR.md). لا يعتبر هذا مصادقة mTLS أو Device Attestation.
