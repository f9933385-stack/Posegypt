# شحنات وتحويلات الفروع في Posegypt — إصدار قاعدة البيانات V8

**مهم:** هذا المسار يدعم فرعين مسجلين **على نفس خادم SQLite المحلي**. لا يدعم حتى الآن فرعين يعمل كل واحد منهما على قاعدة بيانات مستقلة، ولا يضمن إرسال الشحنة عبر الإنترنت أو إعادة المحاولة بين شبكتين متقطعتين.

## دورة عمل الشحنة
1. من صفحة «شحنات الفروع» ينشئ المالك إرسالًا مع الفرع المصدر، والفرع المستلم، والمخزنين، والصنف والكمية بوحدة الأساس.
2. تُخصم الكمية مباشرةً من مخزن المصدر وتُنقل تكلفتها المحاسبية إلى حساب **IN_TRANSIT (مخزون بالطريق)**، ولا تظهر كمية في الفرع المستلم حتى يؤكد وصولها.
3. الصنف المتتبّع بتاريخ الصلاحية يُرسل بتشغيلاته المعروفة على أساس FEFO، ولا يسمح بإرسال تشغيلة منتهية أو محجوزة للبيع.
4. يراجع مدير الفرع المستلم الشحنة ويؤكد الاستلام. يجب أن يكون **مستخدمًا مختلفًا عن الذي أرسلها**؛ فيدخل المخزون بالتكلفة نفسها وتُقفل قيمة حساب البضاعة بالطريق.
5. قبل الاستلام فقط، يمكن للمالك أو مدير الفرع المرسل إلغاء الشحنة مع ذكر السبب؛ تعود الكمية والتشغيلات والقيمة إلى مخزن المصدر.
6. بمجرد الاستلام أو الإلغاء لا يمكن تكرار العملية. العمليات تستخدم معاملة SQLite واحدة مع `Idempotency-Key`، وسجل حركات المخزون وسجل تدقيق المستخدم.

## مسارات API
- `GET /api/v1/branch-shipments?branch_id=...`: قائمة الشحنات التي يكون الفرع مصدرًا لها أو وجهة، للمالك/المدير.
- `GET /api/v1/branch-shipments/<id>`: تفاصيل الشحنة والتشغيلات.
- `POST /api/v1/branch-shipments/dispatch`: `source_branch_id`, `destination_branch_id`, `source_warehouse_id`, `destination_warehouse_id`, `product_id`, `qty_milli`.
- `POST /api/v1/branch-shipments/receive`: `shipment_id`.
- `POST /api/v1/branch-shipments/cancel`: `shipment_id`, `reason`.

كل عملية كتابة تتطلب جلسة مستخدم موثقة ورأس `Idempotency-Key`. ويمكن للفروع عرض الشحنات المرتبطة بها فقط.

## ضمانات محاسبية
- مخزون المصدر ينخفض عند الإرسال، فلا يمكن بيعه مرتين.
- مخزون الوجهة يرتفع عند اعتماد الاستلام فقط.
- أي فشل في تخصيص التشغيلات أو في القيد المحاسبي يلغي العملية كلها.
- يُراجع مدقق `tools/audit_database.py` مخزون الشحنات بالطريق مقابل دفتر الأستاذ، ومطابقة كل شحنة مع حركات إرسالها واستلامها أو إلغائها.

## ما تبقى للإطلاق التجاري
- هذه ليست مزامنة حقيقية بين خوادم مستقلة؛ يلزم بروتوكول آمن لإرسال أوامر النقل وتأكيدات التسلم، ومعرفات موحدة، وتوقيعات واعتمادات ورسائل متكررة وإعادة محاولة مع معالجة تعارضات وأعطال الشبكة.
- لم تتم إضافة استلام جزئي، إثبات تلف/عجز عند الوصول، الحجز أثناء النقل، الموافقات المتعددة على الشحنات مرتفعة القيمة، أو تخطيط طرق التوصيل.
- الأجهزة والطابعات والتكامل الضريبي والمزامنة السحابية والترخيص والتجارب الميدانية ما زالت بوابات إطلاق غير مكتملة.
