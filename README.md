# Kasher | كاشير السوبرماركت المصري

> **Development milestone: executable architecture + transactional POS core, NOT a finished commercial release.**
>
> This repository contains an Arabic-first Flutter application for Windows / Android and a local Dart / Shelf / SQLite branch service. It implements a coherent core of the master specification and identifies the remaining release gates honestly.

## What's included

- **Flutter UI**: Arabic RTL, responsive desktop/tablet layout; login; user management; management dashboard; branch-wide cash shifts; POS with fractional quantities, cash/card/wallet/bank split payment, credit sale; product/stock views; purchase entry; customer/supplier records; expenses; document history.
- **Branch service**: HTTP REST API backed by SQLite in WAL mode, one transaction per write command, explicit `Idempotency-Key`, PBKDF2 password hashing, hashed expiring opaque sessions, tenant + branch-scoped queries, role authorization, immutable audit trail.
- **Financial core**: Egyptian piasters as integer values, quantity in thousandths of the smallest base unit, weighted-average inventory cost by warehouse, sales/purchases, full/partial settlement, customer credit limits, supplier payables, posted returns, expense accounting, stock adjustments, raw-to-packaged preparation, journal balancing and sync outbox.
- **Source**: complete consolidated requirements under [`docs/MASTER_SPEC.md`](docs/MASTER_SPEC.md), executable tests in server and Flutter packages, setup scripts.

## Tech stack

- Flutter SDK / Dart 3.4+ frontend (`app/`)
- Dart / Shelf HTTP branch host (`server/`)
- Local SQLite (foreign keys + WAL) on the host, never shared over SMB
- SQLite database files and local credentials are **not** committed.

## Prerequisites

Install stable Flutter and Dart. Make sure `flutter --version`, `dart --version`, and `flutter doctor` work. On Windows, enable Desktop development with Visual Studio C++ tools. For Android deployment, install Android SDK and USB drivers.

### 1. Bootstrap the branch server

From `server/`:

```powershell
# PowerShell: choose and keep a strong admin password
$env:KASHER_ADMIN_PASSWORD = Read-Host "Admin password"
dart pub get
dart run bin/kasher_server.dart --db=data/kasher.sqlite3 --name="متجر المثال" --branch="الفرع الرئيسي" init
```

Write down the printed `tenant_id`, `branch_id`, `warehouse_id`; no fake data is created. Then:

```powershell
dart run bin/kasher_server.dart --db=data/kasher.sqlite3 serve
```

Default URL: `http://127.0.0.1:8787`. The default binding is restricted to the local machine for safety.

For devices on a **trusted isolated LAN only**:

```powershell
dart run bin/kasher_server.dart --db=data/kasher.sqlite3 --bind=0.0.0.0 --port=8787 serve
```

Allow inbound access only from the branch VLAN or trusted subnet using Windows Firewall. Do not port-forward this service; **plain HTTP over LAN is a development limitation** until TLS/pairing is implemented.

### 2. Generate native Flutter platform scaffolds and run UI

From `app/`:

```powershell
flutter create --project-name kasher_app --platforms=windows,android .
flutter pub get
flutter run -d windows
# Or: flutter run -d <android-device-id>
```

On an Android device, enter the Windows host's trusted LAN address (e.g., `http://192.168.x.x:8787`) instead of localhost. Cleartext HTTP may be blocked by modern Android; implement and configure TLS before any production use. Native Windows / Android scaffold files are generated by Flutter on your machine; this archive intentionally avoids claiming it contains tested binaries.

### 3. Tests

```powershell
cd server
dart test
dart analyze
cd ../app
flutter test
flutter analyze
```

**Build verification note:** these exact Dart/Flutter commands could not be run in the preparation environment because the Dart and Flutter SDKs were absent and outbound internet/DNS was unavailable. The embedded SQL DDL was parsed and successfully applied to in-memory SQLite with foreign keys enabled. Do not deploy on the basis of a static check alone.

## API quick start

`POST /api/v1/auth/login` with `tenant_id`, `username`, and `password` returns a bearer token. `GET /api/v1/branches`, `/products`, `/customers`, `/suppliers`, `/stock?branch_id=...`, `/documents?branch_id=...`, `/dashboard?branch_id=...`, `/audit?branch_id=...`. Writes use JSON plus Bearer token and unique `Idempotency-Key` header. See [`docs/API.md`](docs/API.md).

## Security & accounting guarantees (current implementation)

- SQLite atomic write transactions, foreign keys, explicit no-negative-stock, WAC on each warehouse, double-entry balancing, rejected duplicate write keys, tenant/branch checks, role-based permission checks on server.
- Card and wallet are **recording methods**, not actual bank integrations. There is no connection to payment gateways.
- All financial reports are operational estimates and **not** legal e-invoices, regulatory certification or final audited accounting statements.
- The sync outbox durably records local events; it is **not** yet connected to any cloud synchronization service.

## Operator safety tools (additional source)

- `python tools/verify_schema.py`: independent SQLite DDL and integrity checks.
- `python tools/audit_database.py PATH_TO_DB`: read-only journal, inventory, FK, and document invariant checks.
- `python -m pip install -r tools/requirements-backup.txt` followed by
  `python tools/backup_database.py backup SOURCE.sqlite3 DESTINATION.kasherbak`:
  one-time AES-256-GCM encrypted snapshot. Set `KASHER_BACKUP_PASSWORD` first
  and keep it in a password manager. The script does **not** implement automatic
  backups or cloud sync. See `docs/SECURITY.md`.
- `python -m unittest discover -s tools/tests -v`: local operator-tool tests.

  [`docs/PUBLISH_TO_GITHUB.md`](docs/PUBLISH_TO_GITHUB.md). Sources are imported on feature/import-kasher-source, subject to CI verification.
